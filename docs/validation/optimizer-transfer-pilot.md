# Fresh workflow comparison: October 2, 2026

The opt-in archive workflow did **not** beat the strong iterative Direct comparator
in this descriptive pilot. Its selected programs had **0.824×** Direct's geometric
CPU efficiency (about **21.3% more kernel CPU**), losing five of six family/context
comparisons. Against the historical conservative workflow, it reached **1.113×**
CPU efficiency (about **10.1% less CPU**), winning five of six. The secondary result
does not override the primary result; archive search remains opt-in.

All 18 selected programs were exactly correct on all final cases/repetitions:
2,880 final application/grader trial records passed independent recomputation.
Release gates remained unchanged and passed Direct 5/6, Old 5/6 and New 4/6.
Both New dependency-invalidation selections fell back to the baseline. Selected
artifact quality and delivered-after-gate outcomes are distinct.

| Family | New / Direct CPU efficiency | New / Old CPU efficiency |
|---|---:|---:|
| Dependency invalidation | 0.785× | 0.987× |
| Interval aggregation | 1.021× | 1.192× |
| Prefix/suffix routing | 0.699× | 1.172× |

Ratios above one favor New. The prespecified >25% group-regression diagnostic
found 15/36 New-versus-Direct group/context regressions, worst 2.970× Direct CPU;
New-versus-Old had 2/36, worst 2.398× Old CPU. Every planned context remains in the
mean. [All regimes](optimizer-transfer-regimes.json), [all groups](optimizer-transfer-groups.json),
[selections](optimizer-transfer-selections.json), and [machine-readable results](optimizer-transfer-pilot.json)
retain the detailed hierarchy and costs.

The primary was trusted process-CPU kernel efficiency, using eleven sample batches
and a fixed one-microsecond metric floor, not end-to-end latency. Fresh balanced
AB/BA cohorts measured preselected artifacts. All 18 source identities and final
schedules sealed before any final trial; all 18 within-run and twelve neutral
cross-arm cohorts completed before numerical reporting. Two contexts per family
and synthetic, machine-authored references do not support a universal, production,
SOTA or statistical-certainty claim. Inner cases/repetitions are not independent
optimizer runs.

Twelve development application-author opportunities were followed by one bounded
policy-author attempt, which explicitly retained the initial policy. Six redundant
revision opportunities were skipped without reallocation. The outer stage used
54 opportunities in 18 fresh native contexts. Thus 67 application/meta opportunities
were realized under a ceiling of 73, **without a successful meta-policy mutation
or live component ablation**. Engineering/research inference was additional and
unmetered. Actual served model identity, tokens, inference CPU/duration and native
dollars were unknown; configured opportunity limits were matched, not exact compute.

New used about 8.1% more recorded controller-operation CPU than Direct. These timers
exclude some startup/host work and native inference. Raw trial time includes copies,
hashes and artifact fsync, and is nested inside the inclusive operation timing;
never add both. This measured cost motivates separate shipping-core profiling,
not an unsupported attribution to one feature.

The measured source reported version 0.4.0 and is pinned by module hashes in the
original core record. Later native lifecycle hardening, 0.5.0 packaging, dependency
updates and verification-speed patches are separate evidence. This was native
host orchestration through actual core policies, not verification of live
one-command `automate` or a new standalone CLI backend.
